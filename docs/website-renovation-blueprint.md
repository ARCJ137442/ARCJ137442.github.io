# 个人网站翻新蓝图（公开脱敏版）

> 本版只保留可复用的网站定位、信息架构和实现建议。私人仓库清单、个人日记、未发布理论、身份信息、私人指标、第三方未授权资料均已省略。

## 1. 网站要完成什么

网站应帮助访客在短时间内回答三个问题：

1. 这个创作者关注哪些问题？
2. 哪些作品可以亲自查看或运行？
3. 如何进一步了解、使用或联系？

它不需要复刻完整简历、镜像所有代码仓库，也不应把尚未公开的研究或个人资料作为内容来源。

## 2. 公开与私有的边界

| 内容 | 公开前提 | 处理方式 |
|---|---|---|
| 已公开项目 | 仓库和演示链接允许公开 | 说明项目状态、本人职责和可核验证据 |
| 实验作品 | 不含凭据、用户数据或受限素材 | 标记为实验，不暗示稳定或正式发布 |
| 研究想法 | 来源可公开，且作者确认可分享 | 解释观点与证据边界；私人笔记不直接搬运 |
| 合作成果 | 合作者与组织允许展示 | 分清个人贡献和团队成果 |
| 私人仓库、日志、草稿 | 默认不公开 | 不列名称、规模、目录或内容摘要 |

公开页面应只链接到明确公开的目标。提交记录、Issue 数、下载量等指标要注明统计日期和来源；无法核实时不展示。

## 3. 推荐的信息架构

### 首页

用一段短介绍说明关注的问题和做事方式。再提供少量入口，带访客进入作品、主题或交互演示。避免大段个人自述和冗长技术栈清单。

### 作品

按主题或能力组织，而不是平铺所有仓库。每张作品卡回答：目标、个人职责、当前状态、演示/源码入口和已验证范围。归档项目标为历史作品。

### 文章与笔记

只发布作者确认适合公开的内容。每篇说明更新时间、来源、事实与推论的区分；不要把私人笔记同步目录直接发布。

### 实验室

用可操作演示帮助理解机制。演示数据明确标注为合成或真实；权限、失败状态、重置和移动端降级路径都要可见。

## 4. 叙事与证据

以持续关注的问题串联作品，让读者理解项目之间的关系。每项叙事都应区分：作者的目标、实际实现、公开证据和仍未完成的部分。

“参与”“维护”“提出设计”和“独立完成”不是同一类贡献。只有公开材料支持时才给出精确数量或强结论；计划不写成完成状态，截图不冒充当前版本验收。

## 5. 视觉和交互方向

- 保留一个稳定品牌标志和有限的语义色；颜色表达状态或重点，不替代文字事实。
- 首屏先给价值和可选入口，长篇解释下沉到对应页面。
- 使用真实作品预览、结构图和可操作演示；不要用库存图片制造产品已实现的错觉。
- 用图标减少重复文案，但操作名称、替代文本和键盘焦点仍须可访问。
- 桌面、手机和平板都验证布局、键盘、触摸和滚动；窄屏上不可隐藏关键操作。
- 动效只呈现真实变化，支持减少动态效果；静态模式仍能理解全部信息。

## 6. 分阶段实施

1. **基础整理：** 更新首页介绍、页面标题/描述、导航、主题变量和公开项目清单。
2. **作品详情：** 为活跃项目建立统一模板，保留状态、本人贡献和证据入口。
3. **交互展示：** 选择少量最能说明机制的公开演示，补齐合成数据说明、重置和失败状态。
4. **内容工作流：** 为未来文章或花园设计人工确认、脱敏检查和发布步骤；不自动暴露私有笔记。
5. **验收：** 在实际手机/桌面宽度检查无障碍、资源加载、链接、隐私文本与页面可读性。

## 7. 发布前隐私清单

- 搜索本机绝对路径、私有仓库名、邮箱、电话、身份号码、访问令牌和账号标识。
- 检查截图、图表、源代码片段和 Git 历史是否仍含已移除信息。
- 为每项公开作品核对仓库可见性、许可证、第三方内容和合作方许可。
- 公开更改后访问部署页面，确认页面引用、语言切换、移动端布局和资源状态。

本蓝图只描述公开网站的通用设计方向，不暴露个人履历、私有作品清单或私人日记。
